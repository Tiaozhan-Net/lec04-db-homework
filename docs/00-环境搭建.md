# 环境搭建

只需要装一样东西：**MySQL 8.0.36**。
不需要 Docker，也不需要 Python —— 判分在 GitHub 上跑，本地只用来写 SQL、看数据。

---

## 1. 装 MySQL

装 **MySQL Installer for Windows**，选 **Custom**，勾这几项：

| 产品 | 作用 |
| --- | --- |
| MySQL Server 8.0.36 | 数据库本体（必须） |
| MySQL Workbench | 图形界面，写 SQL 用它（推荐） |
| MySQL Shell | 可选，喜欢命令行再装 |

安装过程中：

- 端口保持 `3306`；
- 设一个 `root` 密码，**记下来**；
- 装完 Windows 服务会自动启动，右下角能看到 MySQL 通知。

版本必须是 **8.0.36**。8.4、5.7 不行——报错码和执行计划会对不上。

## 2. 建两个练习库

### 用 Workbench（推荐）

1. 打开 Workbench，双击本机那个连接（`Local instance MySQL80`），输入 root 密码；
2. 新建查询窗口，执行：

   ```sql
   CREATE DATABASE IF NOT EXISTS hw_clean
     CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
   CREATE DATABASE IF NOT EXISTS hw_legacy
     CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
   ```

3. 左边栏 **Schemas** 里双击 `hw_clean` 选中它（变粗体），然后
   `File → Open SQL Script` 打开 `db/00_clean.sql`，点 ⚡ 执行；
4. 再双击选中 `hw_legacy`，用同样的办法执行 `db/01_legacy.sql`。

做完左边栏的 `hw_clean` 里有 `members` 表（14 行）、`hw_legacy` 里也有 `members` 表（28 行）。

### 用命令行

在仓库根目录：

```powershell
mysql -u root -p --default-character-set=utf8mb4 -e "source db/99_reset.sql"
```

`mysql` 不在 PATH 里的话，用完整路径：

```powershell
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" `
  -u root -p --default-character-set=utf8mb4 -e "source db/99_reset.sql"
```

> 注意：`source` 用的是**相对路径**，所以命令必须在仓库根目录执行。
> PowerShell 不支持 `mysql ... < 文件` 这种写法，用上面 `-e "source ..."` 的写法。

## 3. 三条自检

```sql
SELECT VERSION();                                -- 8.0.36
SELECT @@sql_mode;                               -- 要有 STRICT_TRANS_TABLES
SHOW VARIABLES LIKE 'character_set_database';    -- utf8mb4
```

`sql_mode` 里没有 `STRICT_TRANS_TABLES`，第 4 部分的 `1364` 就不会报出来。
MySQL 8.0 装完默认就是严格模式，一般不用改。

## 4. 本地怎么知道自己写对了

三个档次，随便挑：

### 最准：直接交

push 之后 1–2 分钟，PR 页面 **Checks → autograde → Summary** 就是分数表，
每一项都写了「应为多少、实际多少」。改完再 push，会重跑。

### 对答案：第 1、2 部分

跑完自己的查询，再跑一遍参考答案，两个结果窗口对一眼：

- `grader/solutions/part1_q1.sql` … `part1_q5.sql`
- `grader/solutions/part2_q1.sql` … `part2_q6.sql`

排序不一样、列名不一样、多一行少一行，都算错。

### 逐行对比：第 3 部分

```powershell
mysql -u root -p --default-character-set=utf8mb4 -e "source db/99_check_part3.sql"
```

它会临时建一个 `hw_check` 库，把 `db/01_legacy.sql` 用参考解洗一遍，
再和你本地的 `hw_legacy` 逐列比。第一张表看结论，第二张表是明细，明细为空就是全对。

前提：你的 `part3/clean.sql` 已经在 `hw_legacy` 上跑过了。
这一步要用命令行，Workbench 不支持 `source`。

### 看约束：第 4 部分

```powershell
mysql -u root -p --default-character-set=utf8mb4 -e "source db/99_check_part4.sql"
```

输出 7 行，结果列全是 `OK` 就说明结构齐了。
「真的拦得住吗」还要自己跑一遍 `part4/errors.sql`，看报错码。

## 5. 加分题的数据

20 万行，装完再跑，大约半分钟到一分钟：

```powershell
mysql -u root -p --default-character-set=utf8mb4 -e "source db/02_big.sql" hw_bonus
```

会建 `hw_bonus` 库。不做加分题就不用跑。

## 6. 写 SQL 用什么

- **Workbench**：左边选库，新建查询窗口，写完点 ⚡。适合边看数据边写。
- **命令行**：`mysql -u root -p hw_legacy`，适合快速跑一个文件。
- 任何编辑器都行，但**文件必须存成 UTF-8 无 BOM**（中文专业名会乱码）。

不会用 Workbench 的话，`docs/03-常见问题.md` 里有几条常用的操作。
