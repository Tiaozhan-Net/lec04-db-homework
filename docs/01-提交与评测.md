# 提交与评测

## 1. Fork 并 clone

打开仓库页面，右上角 **Fork**。然后把你的 fork clone 到本地：

```powershell
git clone https://github.com/<你的 GitHub 用户名>/db-hw.git
cd db-hw
```

后面的命令都在这个目录（仓库根目录）执行。

## 2. 建分支

分支名用你的 GitHub 用户名：

```powershell
git checkout -b <你的 GitHub 用户名>
```

## 3. 复制模板

只复制要做的部分：

```powershell
$user = "<你的 GitHub 用户名>"
New-Item -ItemType Directory -Force "submissions/$user"
Copy-Item -Recurse homework/templates/part1 "submissions/$user/"
```

要做多个部分，就把 `part1` 换成 `part2`、`part3`……；也可以一次复制全部：

```powershell
$user = "<你的 GitHub 用户名>"
New-Item -ItemType Directory -Force "submissions/$user"
foreach ($p in "part1","part2","part3","part4","part5","bonus") {
  Copy-Item -Recurse "homework/templates/$p" "submissions/$user/"
}
```

目录名必须是你的 GitHub 用户名（大小写不敏感，但建议保持一致）。只交 `.sql`，不要把模板目录里的 `README.md` 当作业交。

## 4. 写 SQL

用任意文本编辑器打开 `submissions/<用户名>/partN/...` 里的文件，写完保存为 **UTF-8 无 BOM**。在命令行进入对应的库，再用 `source` 执行；库名见每部分的「开始之前」，命令见[环境搭建](00-环境搭建.md) 的「命令行用法」。

提交的 SQL 里不要写 `USE` 或 `CREATE DATABASE`。评测会在自己的库（`hw_p1_dml`、`hw_p3` 等）里执行，写 `USE hw_legacy` 会直接报 1049。

## 5. 本地评测

先按[环境搭建](00-环境搭建.md)确认 MySQL 版本、装好 Python 和评测依赖，并设置 `MYSQL_PASSWORD`。然后在仓库根目录运行：

```powershell
python grader/run.py --part 1 --user <你的 GitHub 用户名>
```

`--part` 可以是 `1`、`2`、`3`、`4`、`5`、`bonus`、`all`，也可以写 `1,2`。看到本部分满分即可；有 ❌ 的项，按“说明”列改。

## 6. 提交 PR

```powershell
git add submissions/<你的 GitHub 用户名>
git commit -m "hw: <你的 GitHub 用户名>"
git push -u origin <你的 GitHub 用户名>
```

回 GitHub 点 **Compare & pull request**：

- 标题：`hw: <你的 GitHub 用户名>`
- 描述里的清单勾一下

## 7. 看分数

PR 页面往下拉，**Checks → autograde → Summary**。第一张表是每个部分的得分，下面是明细，说明列会写“应为多少、实际多少”。

改完再 push 一次，自动重跑，分数以最后一次为准。

## 会被拦住的情况

| 情况 | 结果 |
| --- | --- |
| 改了 `submissions/` 以外的东西 | 直接失败 |
| 目录名和 PR 作者不一致 | 直接失败 |
| 一个 PR 里有两个人的目录 | 直接失败 |
| 单个 `.sql` 超过 64 KB | 直接失败 |
| 出现 `DROP TABLE`、`DROP DATABASE`、`TRUNCATE`、`INTO OUTFILE`、`LOAD_FILE` | 直接失败 |
| 脚本里写了 `USE` / `CREATE DATABASE` | 不被 CI 拦截，但评测执行时报 1049，相关文件或脚本拿不到分 |
| 某个部分没交 | 只有那部分是 0 分 |
