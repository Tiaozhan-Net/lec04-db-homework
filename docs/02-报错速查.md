# 报错速查

按错误码查。左边是 MySQL 的原话，右边是「人话 + 怎么办」。

| 错误码 | MySQL 说什么 | 人话 | 怎么办 |
| ---: | --- | --- | --- |
| `1062` | `Duplicate entry 'xxx' for key 'uk_student_id'` | 这个值已经存在了，撞上唯一索引 | 换一个学号；或者先查一下有没有这条 |
| `1048` | `Column 'name' cannot be null` | 这一列不允许 `NULL`，你给了 `NULL` | 换成空串之外的合法值；空串会被 CHECK 拦（`3819`） |
| `1364` | `Field 'name' doesn't have a default value` | 这列没有默认值，你又没写它 | 把该列的列名和值补上 |
| `3819` | `Check constraint 'chk_members_xxx' is violated` | `CHECK` 规则没通过 | 看约束名：`score` 越界、`name` 空、学号不是 8 位、专业不在白名单、班级格式不对 |
| `1064` | `You have an error in your SQL syntax` | 语法错 | 常见：写了 `ALTER COLUMN x SET NOT NULL`（MySQL 没有），要用 `MODIFY COLUMN x ... NOT NULL` |
| `1093` | `You can't specify target table 'members' for update in FROM clause` | `UPDATE`/`DELETE` 里不能直接子查询同一张表 | 把子查询包成派生表：`DELETE m FROM members m JOIN (SELECT ... FROM members) t ON ...` |
| `1292` | `Truncated incorrect datetime value` | 字符串转 `DATETIME` 失败 | 第 3 部分的日期没洗干净，先统一成 `YYYY-MM-DD HH:MM:SS` 再做第 4 部分 |
| `1406` | `Data too long for column 'xxx'` | 值比列定义长 | 检查列长度，或者你多写了空格 |

## 评测里不会出现的两个

- `1292`：评测时第 4 部分跑在**已经洗干净**的数据上，所以不会遇到。只在本地「第 3 部分没做完就做第 4 部分」时出现。
- `1406`：正常写不会遇到。

## 拿不准的时候

```sql
SHOW CREATE TABLE members\G
SELECT @@sql_mode;
```

第一条能看出现在到底有哪些约束和类型，第二条能看出是不是严格模式。
