# 第 1 部分 会用：增删改查（35 分）

## 1. 情景

社团招新第一天。你手里有几份纸质报名表要录进 `hw_clean.members`，还要复核一条分数、删掉一条重复登记的记录。

忙完这些，社长要几张报表：85 分以上的都是谁、姓张的有几个、分数最高的三位、每个专业各多少人。

这一部分练的就是这些最日常的动作：`INSERT`、`UPDATE`、`DELETE`、`SELECT`。

## 2. 数据与准备

- 表：`hw_clean.members`，14 行规范数据，已有约束。
- 第一次（练习库还没建）：


- 每次重来（只重置这张表）：

## 3. 要做什么

### 3.1 `01_dml.sql` 四条语句

四条写在一个文件里，**按顺序执行**。表一开始 14 行，这一节做完是 17 行。

#### 第一条：录进一个新人

有人现场填了表，把这一条插进去。`name` 写你的 GitHub 用户名，评测按 PR 作者核对；其他字段按下表给。

| 字段 | 值 |
| --- | --- |
| `student_id` | `20239001` |
| `name` | 你的 GitHub 用户名 |
| `class_name` | `2024-1` |
| `major` | `软件工程` |
| `score` | `90` |
| `joined_at` | `2025-10-01 09:00:00` |

#### 第二条：一条语句录三个人

三个人是一起报的名，要求**用一条 `INSERT`** 写进去，不要拆成三条。

| student_id | name | class_name | major | score | joined_at |
| --- | --- | --- | --- | ---: | --- |
| `20239002` | 张同学 | `2023-1` | 计算机科学与技术 | 77 | `2025-10-02 10:00:00` |
| `20239003` | 李同学 | `2023-2` | 软件工程 | 82 | `2025-10-02 11:00:00` |
| `20239004` | 王同学 | `2024-1` | 数据科学与大数据技术 | 68 | `2025-10-02 12:00:00` |

> **讲义没讲：** 一条 `INSERT` 可以带多组 `VALUES`，逗号隔开就行：`INSERT INTO t (a, b) VALUES (1, 2), (3, 4), (5, 6);`

#### 第三条：改一个人的分数

学号 `20230003` 补交了材料，复核之后分数改成 `80`。

改一条记录要带 `WHERE`，而且用**学号**定位。评测库的自增 `id` 和本地不一样，写 `WHERE id = 3` 会改不到人。

#### 第四条：删一条记录

学号 `20230008` 退社了，这条记录要删掉。这是硬删除，软删除在第 5 部分才出现。

同样用学号定位，带 `WHERE`。

### 3.2 五条查询

一个文件一条 `SELECT`，不要 `SELECT *`。列名要和下面写的一模一样，评测比列名。

#### `02_q1.sql` 85 分以上的人

社长想知道哪些人过了 85 分，按分数从高到低看前五名。

- 输出列：`name`、`score`
- 排序：`score DESC, student_id ASC`
- 截断：前 5 条

85 分以上有 7 个人，前五名里会出现两个 92 分、两个 88 分，所以第二排序键不是可写可不写的。

#### `03_q2.sql` 姓张的同学

整理通讯录，先把姓张的挑出来。

- 输出列：`name`、`student_id`
- 排序：`student_id ASC`
- 用 `LIKE` 做前缀匹配

#### `04_q3.sql` 分数最高的三位

- 输出列：`name`、`score`
- 排序：`score DESC, student_id ASC`
- 截断：前 3 条

#### `05_q4.sql` 某个专业有多少人

- 统计专业是 `计算机科学与技术` 的人数
- 输出列：`cnt`，只有一行
- 列名写成 `COUNT(*) AS cnt`

#### `06_q5.sql` 每个专业各多少人

- 输出列：`major`、`cnt`
- 排序：`cnt DESC, major ASC`
- 人数相同的专业按专业名升序，不然排序不稳定
