# 第 3 部分：洗得干净——清洗（25 分）

第 2 部分查出来的毛病，现在要动手治。`hw_legacy.members` 有 28 行，洗完要剩 14 行；洗完的表必须能直接加约束：学号唯一、六列非空、`joined_at` 能转成 `DATETIME`。哪一类数据没洗到位，第 4 部分加约束时就会失败。

交一个 `part3/clean.sql`，原地清洗。只允许改数据：`UPDATE`、`DELETE`，可以包在事务里；不要写 `DROP TABLE`、`DROP DATABASE`、`TRUNCATE`，不要建新表再改名，也不要写 `USE` 或 `CREATE DATABASE`。

> **开始之前**
>
> - 读：第 2 部分的六条查询结果；`TRIM`、`STR_TO_DATE`、`DATE_FORMAT`、`CASE`、派生表。
> - 数据：`hw_legacy.members`，28 行脏数据，洗完 14 行。
> - 如果第 2 部分刚跑过 `01_legacy.sql`，这里不用再跑；重复跑会把表重置回 28 行脏数据。
> - 从零开始时，在仓库根目录执行 `mysql -u root -p --default-character-set=utf8mb4 -e "source db/01_legacy.sql" hw_legacy`。
> - `part3/clean.sql` 模板里已经写好 `START TRANSACTION;` 和 `COMMIT;`，把你的清洗 SQL 写在中间；洗错了可以 `ROLLBACK`，不用重新灌数据。

## 任务：按顺序清洗

下面 8 步有先后依赖，建议按顺序写。每一步先想清楚“现在处理哪一类行”，再动手。

讲义没讲的函数先看这里：

| 写法 | 作用 |
| --- | --- |
| `TRIM(x)` | 去掉字符串首尾空格 |
| `x REGEXP '...'` | 在 `WHERE` 里做正则匹配；`NOT REGEXP` 取反 |
| `REPLACE(x, 'a', 'b')` | 把字符串里的 `a` 换成 `b` |
| `STR_TO_DATE(s, fmt)` | 按 `fmt` 把字符串解析成日期 |
| `DATE_FORMAT(d, fmt)` | 把日期按 `fmt` 格式化回字符串 |
| `CONCAT(a, b, ...)` | 拼接字符串 |
| `LEFT(x, n)` / `SUBSTRING(x, pos, len)` | 取左边 n 个字符 / 从 pos 取 len 个字符 |
| `CASE WHEN ... THEN ... ELSE ... END` | SQL 里的 if-else |
| `MIN(x)` | 最小值 |
| `ROW_NUMBER() OVER (...)` | 分组内编号，用来去重 |

### 1. 去掉四列的首尾空格并写回

第 2 部分已经看到，`student_id`、`name`、`class_name`、`major` 都有前后带空格的值。清洗的第一步不是删，而是把这四列的 `TRIM` 结果写回原列。后面的学号正则、班级正则和专业白名单都假设值已经去过空格；如果只在 `SELECT` 里 `TRIM` 而不写回，第 4 部分加约束时会被拦下。

> **要求**
>
> 用一条 `UPDATE` 同时处理四列，把 `TRIM` 后的值写回 `members`。

**提示**
- `TRIM(NULL)` 的结果还是 `NULL`，不会变成空串；空值留到第 2、3 步再删。
- 不要只写 `SELECT TRIM(...)`；清洗要改表。
- 一条 `UPDATE` 写四列觉得别扭，也可以拆成四条，但每列都要写回。

### 2. 删掉空学号和非 8 位学号

学号是后面唯一索引和 `CHECK` 的基础。上一步已经去过空格，这一步只处理两类行：`NULL` 或空串，以及去掉空格后不是 8 位数字的值（7 位、9 位、含字母）。这两种行都留不到第 4 部分，直接删掉。

> **要求**
>
> 删除 `student_id` 为 `NULL`、为空串、或不匹配 `^[0-9]{8}$` 的行。

**提示**
- `NOT REGEXP` 遇到 `NULL` 返回 `NULL`，不会算“真”，所以 `IS NULL` 要单独写。
- 全空格在第 1 步已经变成空串；如果你跳过了第 1 步，这里要先用 `TRIM` 判断。
- 学号 `' 20230020 '` 去掉空格后是 8 位，应该保留，不应该删。

### 3. 删掉空姓名

姓名的毛病有三种：`NULL`、空串、全是空格。第 1 步已经把前后空格去掉，全空格会变成空串；这一步把 `NULL` 和空串的行删掉。

> **要求**
>
> 删除 `name IS NULL` 或 `name = ''` 的行。

**提示**
- 先 `TRIM` 再判断是不是空，顺序反了会把全空格的名字留下来。
- 不要用 `name = NULL` 判断 `NULL`；SQL 里 `NULL = NULL` 的结果还是 `NULL`，要用 `IS NULL`。
- 姓名前后带空格但中间有字的行，第 1 步已经处理，不需要删。

### 4. 统一报名时间（必须在去重之前）

`joined_at` 现在是 `VARCHAR`，三种写法混在一起：

```text
2025-09-01 08:00:00
2025/09/01 08:00:00
2025-09-01T08:00:00
```

只认第一种。洗完这一列要能直接被 `MODIFY COLUMN ... DATETIME(3)` 转过去，不需要再兜底。

这一步必须在第 8 步去重之前做。去重要用 `MIN(joined_at)` 找最早报名时间；如果日期格式不统一，字符串比较会把 `2025/09/01` 排在 `2025-10-01` 后面，留下错误的那一条。

> **要求**
>
> 把 `joined_at` 统一成 `YYYY-MM-DD HH:MM:SS`，写回原列。

**提示**
- `STR_TO_DATE(字符串, '%Y-%m-%d %H:%i:%s')` 把字符串按指定格式解析成日期；`DATE_FORMAT(日期, '%Y-%m-%d %H:%i:%s')` 再格式化回字符串。`%i` 是分钟，不是 `%m`。
- 先用 `REPLACE(joined_at, 'T', ' ')` 处理 `T`，再用 `REPLACE(..., '/', '-')` 处理斜杠；两个 `REPLACE` 可以嵌套。
- 日期列是 `VARCHAR`，洗完还是字符串，但要保证格式正确；第 4 部分会把它改成 `DATETIME(3)`。

### 5. 统一班级

三种写法指的是同一个班：

| 现在 | 洗完 |
| --- | --- |
| `2023-1` | `2023-1` |
| `2023级1班` | `2023-1` |
| `2023 1班` | `2023-1` |

规则是“四位年份 + `-` + 班号”，其他班级同理。洗完只留 `YYYY-N` 这种形式，因为第 4 部分的 `CHECK` 就按这个写。

> **要求**
>
> 把 `2023级1班`、`2023 1班` 这类写法改成 `2023-1`；已经是 `YYYY-N` 的保持不变。

**提示**
- 两种待改写法只有第 5 个字符不同，班号都在第 6 位：

  | 位置 | 1–4 | 5 | 6 | 7 |
  | --- | --- | --- | --- | --- |
  | `2023级1班` | `2023` | `级` | `1` | `班` |
  | `2023 1班` | `2023` | 空格 | `1` | `班` |

  `LEFT(class_name, 4)` 取年份，`SUBSTRING(class_name, 6, 1)` 取班号，再用 `CONCAT(..., '-', ...)` 拼起来。
- 只改匹配 `^[0-9]{4}(级| )[1-9]班$` 的行；已经是 `YYYY-N` 的行不要重复拼接。
- 第 1 步已经去过首尾空格；如果班级中间有别的空格，这条正则不会命中，需要单独看。

### 6. 统一专业

只留三个值：`计算机科学与技术`、`软件工程`、`数据科学与大数据技术`。现在表里是这些写法：

| 现在写成 | 改成 |
| --- | --- |
| `计算机` / `计科` / `计算机科学` | `计算机科学与技术` |
| `软件` / `软工` | `软件工程` |
| `大数据` / `数据科学` | `数据科学与大数据技术` |

> **要求**
>
> 用一条 `UPDATE` 把同义词统一成三个白名单值；其他值保持不变。

**提示**
- `CASE WHEN 条件 THEN 值 WHEN ... ELSE 值 END` 就是 SQL 里的 if-else，可以直接写在 `SET` 右边。
- `ELSE major` 要保留，否则不在同义词表里的值会被写成 `NULL`。
- 第 1 步已经去过首尾空格；如果专业值中间有空格，`IN` 匹配不到，需要单独处理。

### 7. 处理分数

分数是 `DECIMAL(5,2)`，正常范围 0 到 100。表里有 `NULL`、负数、超过 100 的值。

| 现在 | 洗完 |
| --- | --- |
| `NULL` | `0` |
| 小于 0 | `0` |
| 大于 100 | `100` |
| 0 到 100 之间 | 不动 |

> **要求**
>
> 把 `NULL` 和负数改成 `0`，把大于 100 的值改成 `100`。0 分是合法值，不要删掉或改掉。

**提示**
- 同一列里三种情况对应两个结果，写成两条 `UPDATE` 更清楚。
- `WHERE score IS NULL OR score < 0` 和 `WHERE score > 100` 是两条独立的规则。
- `20230028` 本来就是 `0.00`，它不在任何一条 `WHERE` 里，不会被误改。

### 8. 去重：先留最早报名，再留最小 id

同一个学号有多条记录时，**只留报名时间最早的那一条**；报名时间也一样的，留 `id` 小的那一条。

这个顺序不能反：如果先按 `id` 留，`20230001` 会留下 id 小的 9 月记录，而不是 10 月那条；如果日期还没统一，字符串比较会把 `2025/09/01` 排在 `2025-10-01` 后面，留下错误的一条。

> **要求**
>
> 最终每个 `student_id` 只保留一行。先去重“时间较晚”的行，再在时间并列的行里去掉 id 较大的行。

**提示**
- MySQL 不允许在 `DELETE` 的 `WHERE` 子查询里直接引用同一张表，会报 1093。把子查询包成派生表再 `JOIN`：
  ```sql
  DELETE m FROM members m
  JOIN (SELECT ... FROM members GROUP BY ...) d ON ...
  WHERE ...;
  ```
- 第一步用 `MIN(joined_at)` 找出每个学号要保留的时间；第二步用 `MIN(id)` 处理时间并列。
- 也可以用 `ROW_NUMBER() OVER (PARTITION BY student_id ORDER BY joined_at, id)`，只删 `rn > 1` 的行。
- 去重前先确认第 4 步的日期已经统一，否则 `MIN(joined_at)` 的比较结果不可靠。
