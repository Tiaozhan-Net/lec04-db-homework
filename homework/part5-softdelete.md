# 第 5 部分 删得回来：软删除迁移（10 分）

## 1. 情景

有位同学退社，管理员直接 `DELETE` 了。

一周后他想回来，同一个学号插不进去——`uk_student_id` 还记着他，虽然那条记录已经不在表里了。

这次要把「删除」改成软删除：记录留着，只是标记成已取消。然后处理随之而来的问题：唯一索引还认不认这个学号。

## 2. 数据与准备

- 表：`hw_legacy.members`，第 4 部分做完的终态（已清洗、已加约束）。
- 准备：三条依次执行（`<你的用户名>` 换成自己的）。

  ```powershell
  mysql -u root -p --default-character-set=utf8mb4 -e "source db/01_legacy.sql" hw_legacy
  mysql -u root -p --default-character-set=utf8mb4 -e "source submissions/<你的用户名>/part3/clean.sql" hw_legacy
  mysql -u root -p --default-character-set=utf8mb4 -e "source submissions/<你的用户名>/part4/constraints.sql" hw_legacy
  ```

  加列和加索引都不能重复执行，每次改完要重来，都从这三条开始。自己写的那两条还没跑通的话，用 `grader/solutions/part3_clean.sql` 和 `part4_constraints.sql` 代替。

## 3. 要做什么

三个文件，按 `05a` → `05b` → `05c` 的顺序执行。

### 3.1 `05a_softdelete.sql` 加列，改成软删除

先给表加一列 `deleted_at DATETIME(3) NULL`，默认 `NULL` 表示「还在社里」。

然后处理学号 `20230002` 的取消报名。这一次不写 `DELETE`，改成把 `deleted_at` 写成当前时间 `NOW(3)`。

做完之后：表里还是 14 行，其中 13 行活跃。

### 3.2 `05b_migrate.sql` 把唯一索引改成「活跃才唯一」

现在的 `uk_student_id` 是「学号唯一」，不管这条记录是否已删除。所以一个人被软删除之后，就再也报不上名。

改成：**同一个学号最多只能有一条活跃记录**，已软删除的记录不占位。索引名还叫 `uk_student_id`。

> 这一题的关键是：怎么让「已删除」的记录在唯一索引里不互相冲突，同时又不放过两条活跃记录。

改完以后，下面四件事应该成立：

| 情况 | 结果 |
| --- | --- |
| 两条活跃记录同学号 | 报 `1062` |
| 一条已软删除 + 一条新的活跃 | 允许 |
| 把旧的已删除记录恢复成活跃，而新的还在 | 报 `1062` |
| 两条都已软删除 | 允许 |

### 3.3 `05c_reinsert.sql` 重新报名

学号 `20230002` 再报一次名，必须成功。其余字段自己给合法值。

### 3.4 本地手测

按顺序跑完三个文件，然后在查询窗口里把这四件事试一遍（每试完一条记得撤销，或者重新跑一遍三个脚本）：

| 做什么 | 期望 |
| --- | --- |
| 插一条活跃记录，学号和某条已有活跃记录相同 | `1062` |
| 把某条活跃记录的 `deleted_at` 设成 `NOW(3)`，再插同号活跃记录 | 成功 |
| 上一步插完之后，把旧行的 `deleted_at` 改回 `NULL` | `1062` |
| 把两条都软删除，再插一条同号活跃记录 | 成功 |

四条都对，行为测试就都过了。
